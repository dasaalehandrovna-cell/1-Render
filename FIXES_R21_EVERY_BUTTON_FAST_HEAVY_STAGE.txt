Пер-R21 — EVERY BUTTON FAST / HEAVY SECOND STAGE

Главное архитектурное правило
-----------------------------
Любая Telegram-кнопка сначала обслуживается Render #1 FAST. Кнопка не бывает «тяжёлой» сама по себе.
FAST-этап: принять callback -> ACK -> открыть/обновить окно -> применить короткое локальное изменение -> поставить heavy-job.
HEAVY-этап: CSV/XLSX/Google/backup/MEGA/экспорт и другие split-capable тяжёлые операции выполняются Render #2.

Что изменено относительно R20
-----------------------------
1. Убрана маршрутизация callback по признаку heavy/light. Все нефинансовые callback идут в FAST window lane.
2. Финансовые мутации остаются в отдельной короткой chat-serial очереди только ради точного порядка записей. Тяжёлые кнопки в эту очередь не попадают.
3. Настройка пары пересылки больше не использует общий GENERAL pool; она идёт через FAST_UI с pair-key.
4. submit_interactive_file_job в пользовательской части больше не делает Redis/Key Value RTT, save_data, backup или тяжёлую генерацию до возврата из callback.
5. Distributed single-flight lock перенесён в background dispatch runner.
6. Файловый single-flight теперь chat+kind, а не один глобальный ключ на весь бот.
7. Split-capable exports получают отдельный короткий heavy-dispatch pool, который только передаёт задачу Render #2.
8. Транзитное окно прогресса не сохраняется как durable state — после deploy оно может безопасно исчезнуть.
9. FAST_UI workers: 6. Тяжёлая работа не должна занимать FAST callback workers.
10. В owner READY-сообщении имя релиза: «Пер-R21».

Сохранение/восстановление
-------------------------
R20/v262 durable capsule сохранён без изменения формата и Redis key для бесшовного перехода R20 -> R21.
Config generation и user-state seq по-прежнему восстанавливаются независимо и не могут откатиться назад.

Важно
-----
Диагностические артефакты, которым нужны живые данные именно процесса FAST (например runtime текущего процесса),
выполняются в низкоприоритетном отдельном export pool и никогда не занимают callback lane. Основные экспорт/Google/backup/MEGA split-задачи идут на HEAVY.
